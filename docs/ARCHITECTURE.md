# AniTV architecture

AniTV is one Kotlin Android `app` module. Compose for TV owns navigation and screens; `LibraryStore` owns local favorites and progress; `AnimeDetailCache` owns cached title metadata and poster files; `HiAnimeSource` owns HiAnime requests and parsing; `OpeningSkipSource` owns MAL title matching and AniSkip timing requests; `ProcessRules` owns one startup `RulesRepository`; `ProcessUpdates` owns one foreground release updater; `SubtitleTranslator` owns Google/DeepL API requests; Media3 owns playback.

```text
Home → Search/results or local library → detail + episodes → available SUB/DUB → HLS + optional VTT player
Home featured Continue watching / detail Continue watching → saved episode + audio + position → fresh stream → player
        ui/AniTVApp                        HiAnimeSource       Media3
                         LibraryStore ← progress/favorite/completed
                         AnimeDetailCache ← description/facts/poster/timestamp
Playback Episodes → modal episode sidebar → selected episode + current SUB/DUB → fresh stream
Home → Settings → Android LocaleManager → English or Turkish resources
AniTVApp → TV WebView/HTTP User-Agent → HiAnimeSource + Media3 HTTP requests
Settings → TranslationSettingsStore → Android Keystore → provider key
Playback caption menu → TranslationSettingsStore → target language + caption style
Playback → HiAnimeSource VTT cues → SubtitleTranslator batches → timed Media3 SubtitleView overlay
Playback → romanized/display title → MAL exact match → AniSkip opening interval → Skip Opening selection → Media3 seek
```

## Flow

1. `AniTVApp` sends a query to `HiAnimeSource.search()` on `Dispatchers.IO`. The source reads `https://hianime.at/search?keyword=...` and parses `.film_list-wrap .flw-item` cards into `Anime` records, including each result's detail link.
2. Selecting a result or saved title loads episodes and details independently. `episodes()` reads `/api/theme/episode/list/{animeId}` and extracts `a.ep-item[data-id]`. `details()` reads the title page, parses `#ani_detail` for description and facts plus `.anisc-poster img[src]` for the portrait poster URL, and falls back to a search by title for older saved entries without a detail link.
3. `AnimeDetailCache` returns stored details and image bytes immediately. Entries under 24 hours old skip a network request. Older entries stay visible while `HiAnimeSource` fetches new metadata and poster bytes; a missing cached image also triggers refresh. The changed cache metadata key invalidates earlier wide-cover entries, so they refresh on first open. Android may evict files from the cache directory, which results in a new fetch. Home Continue watching and Favorites reuse this behavior through `rememberAnimeArtwork`; `LibraryContent` keeps favorite filtering and stable title keys, while the coordinator supplies card content. Each favorite card remains selectable during loading or artwork failure. Currently watching and Completed retain their existing text rows.
4. Selecting an episode calls `servers()`. The source reads `/api/theme/episode/servers?episodeId=...`; `parseServers()` returns only available ZokoAnime `sub`/`dub` entries with validated HTTPS embed links. When one audio version exists, the app starts it directly. When both exist, `EpisodeContent` offers Subtitled and Dubbed buttons. `stream(server)` reads the selected embed, and `parsePlayer()` decodes `window.__P` into an HTTPS HLS URL and optional VTT subtitle URL. SUB retains its subtitle requirement; DUB can play without captions. There is no dub language picker or audio translation; dubbed audio uses the source version. An error allows retrying the selected version or choosing another available version.
5. `Playback` builds a Media3 `MediaItem` and attaches an external VTT track when present. A dub without a VTT track disables the caption button and translation work. `DefaultHttpDataSource` sends the embed origin as `Referer` for stream and subtitle requests. It uses the same TV-derived User-Agent as `HiAnimeSource`. `PlayerView` renders video; Compose buttons handle the remote. Media3 track groups populate the optional quality selector. The bottom controller places Episodes at the left, previous/play-pause/next in the center, and Settings at the right. It uses filled Material Icons from the BOM-managed Compose Material Icons Extended dependency. The focusable progress slider sits above the buttons and displays elapsed/total time. Up from any controller button focuses the slider; Left/Right there seek by minus/plus ten seconds, clamped to the media bounds. Down returns to play/pause; Up again hides the entire controller. Down or Select reopens hidden controls with play/pause focused. Controls also hide after six seconds of play without remote input; Settings and Episodes suspend that timeout. Unknown-duration or unseekable media keeps progress visible without accepting seeks. `ForegroundPlayer` observes the Activity lifecycle and creates a player only at Start. At Stop (including the physical Home button), it pauses, saves progress, and releases synchronously. Returning creates a new player at the saved position with the previous play/pause state. A late stream response while stopped cannot start playback. `DisposableEffect` removes the observer and releases on composition exit; repeated cleanup is harmless. Player changes restart translation and progress jobs; `PlayerView` detaches on disposal.

Previous/next use the adjacent entries in the existing source episode list, without assuming numeric episode labels or IDs. Missing current entries, list loading, and first/last boundaries disable unavailable skip actions and remove them from D-pad focus. Both skips and sidebar selections use the same callback to save outgoing progress and request fresh playback with the current SUB/DUB preference.

Playback's Episodes control opens `EpisodeSidebar` in a modal Compose Dialog. The sidebar receives title/current episode, the existing episode list, and independent loading/error state from the coordinator. Its keyed LazyColumn initially scrolls/focuses the current episode by ID, falling back to the first available episode or Close if empty. The current episode stays visible in the sidebar header and has a play icon, text marker, selected semantics, and distinct row background. The dialog confines focus and handles Back; dismissal returns focus to Episodes. The controls timeout pauses while the sidebar is open. Opening, navigating, or closing the sidebar does not change play/pause state. Selecting the current row only dismisses; selecting a different episode saves the outgoing position, then asks the coordinator to load it with the current audio version. The old player releases through the existing lifecycle/disposal path. Composition keys keep its cleanup callback bound to the outgoing anime/episode. A list retry calls `HiAnimeSource.episodes()` without clearing the active stream; stale title generations cannot replace the new title's list.

6. Playback Settings is a modal Dialog that confines D-pad focus. It contains quality selection and the existing Captions settings (the requested lyrics/subtitle controls). Quality stays on Auto when only one supported variant is available; captions are disabled when the stream has no subtitle track. Back returns through quality/caption/language/style pages, then closes Settings and restores focus to its controller button. Menus scroll within the TV viewport for large text. Playback's caption menu starts with a focused toggle labeled “Captions: on” for Original/Translated and “Captions: off” for Off. The toggle keeps the menu open and retains focus, remembers the previous enabled mode within that menu instance, and falls back to Original when translation is unavailable. Enabling an initially-off menu also selects Original. Separate Original and Translate choices remain available. Translate requires a configured provider and key. The language picker saves one of 15 target languages in `TranslationSettingsStore`; an unset target follows the app/TV locale. The style picker saves font, percentage size, background color, and text color in the same store. Original and translated cues use Media3 `SubtitleView` with the same style; translated cues appear in a timed overlay while the native text track is disabled. The default is white sans serif at 24 sp (100%) on an 80% opaque black rectangular background. Translation fetches and parses timed VTT through `HiAnimeSource`. `SubtitleTranslator` sends up to four cue strings per HTTPS request. The app translates the current/following cues first, then advances the batch as playback approaches the end of translated cues. Changing language restarts batching at the current playback position. On VTT or API failure, playback re-enables the original Media3 subtitle track and shows a notice.
7. `LibraryStore` saves favorites, completion, and one last episode/position per title as JSON in private `SharedPreferences`. Playback saves progress every five seconds and on exit. The completed archive changes only through the detail-screen button. Currently watching filters saved progress to non-completed titles. `continueWatching()` selects the eligible entry with the latest progress `watchedAt`; favorite/completion edits do not update that time. Ties, including older records without watch time, retain list order. The home section adds its heading and card only when an eligible title exists; no history, zero progress, and completed-only libraries add no section. It features one title; the existing Currently watching collection remains available for all titles. Detail offers resume for any title with a positive saved position. `resumeEpisode()` reconstructs the saved episode without advancing it, and the existing player seeks to the matching stored position. The coordinator chooses the saved audio if available; otherwise it asks the user to select available audio. It fetches fresh server/embed data instead of saving expiring stream URLs. Title/episode-list loads keep a separate request generation from stream loads so home resume can populate the detail page for Back while playback prepares.
8. Settings reads and sets Android `LocaleManager.applicationLocales`. An empty locale list follows the system; explicit `en` or `tr` choices persist in Android and cause a configuration change. `TranslationSettingsStore` encrypts the API key with Android Keystore and stores the provider choice and caption style in private preferences. Android string resources localize app controls and source errors. `HiAnimeSource` emits typed failure codes without depending on Android resources.

The UI uses `remember` state for query, results, selection, loading, and errors. The page uses `rememberSaveable` so Settings remains open after a language change. Separate title and transient request counters ignore late responses after another selection or Back. Search query and results are not persisted across process death; library and detail cache state are.

## Opening skipping

`HiAnimeSource.parseSearch()` optionally reads `data-jname` from the configured title element into `Anime.japaneseTitle`; the visible title and search behavior stay intact. The optional library JSON field preserves it across restarts. Older entries without it remain readable; playback refreshes the matching HiAnime search entry by source ID before lookup. Missing optional markup still permits exact matching by display title. This attribute is compiled, not a new signed-rules schema field.

The manual opening button defaults to enabled. Playback Settings saves the existing toggle under private `playback` preferences (`skip_openings`), independent of captions, translation, and library progress; an older Off preference still disables it. When enabled and the foreground player reports a known seekable duration, a cancellable Compose effect performs lookup on `Dispatchers.IO`. The preferred romanized title is sent to MAL's fixed `/search/prefix.json?type=anime&keyword=...&v=1` endpoint. Only a unique positive anime ID whose name exactly matches the romanized or display title, ignoring case and repeated whitespace, is accepted. There is no fuzzy-first-result or HiAnime-ID-to-MAL-ID assumption.

`OpeningSkipSource` sends the MAL ID, source episode number, and actual duration in seconds to AniSkip `/v2/skip-times/{malId}/{episodeNumber}?types[]=op&episodeLength=...`. Decimal episode labels are supported; nonnumeric labels do not request timings. Only finite `op` intervals with nonnegative start, increasing endpoints, an end before the media ends, and a reported duration within 30 seconds are accepted. Identical intervals deduplicate; conflicting intervals disable skipping. Duration is sent so AniSkip can select a suitable cut; timestamps are never stretched or shifted. Requests reject redirects, use five-second connect/read timeouts, and limit each JSON body to 256 KiB. No API key, media URL, subtitle text, or saved watch position is sent. MAL receives the title query; AniSkip receives ID/episode/duration. Both receive the app's User-Agent and ordinary connection metadata.

The existing 250 ms playback poll updates position/duration without seeking. The pure `openingSkipTarget()` returns an endpoint only inside a valid interval, with enabled seekable media and known duration. `PlaybackControls` shows a labeled TV Button in a transparent row above the controller panel, aligned with the slider’s right edge during that interval, including while paused. The panel owns its background and insets independently, so the prompt cannot change its bounds or the slider position. Button content owns its minimum height and symmetric padding inside a centered Box; outer row spacing stays outside the button. It also shows a standalone lower-right prompt when the rest of the controller is hidden. Appearance never requests focus or changes position. Up from the slider focuses Skip Opening; Down returns to the slider; another Up from the button hides the controller. When hidden, Up focuses the standalone prompt, while Down/Select from video retain the existing show-controls behavior. Button focus suspends the six-second controller timeout. Expiry or a completed skip returns its focus to the slider when visible, otherwise to video.

Only selecting Skip Opening invokes the player's seek. Playback rechecks the actual current position/duration, preference, seekability, and closed menus before seeking to the endpoint, saving progress, and showing the existing three-second nonfocusable notice. It preserves play/pause state. There is no consumed-once state: seeking back into the opening offers the button again. At the end timestamp the button disappears; disabled/unknown-duration/unseekable media has no prompt, and modal menus hide it. Toggling Off prevents new lookups and hides the button; toggling On retries lookup. Missing matches/times, bad data, and network failures leave ordinary playback available and show a localized Settings status. No repeated network retry, ending/mixed-opening/recap skips, manual MAL picker, or persistent timing cache is included.

The [ani-skip README](https://github.com/synacktraa/ani-skip) supplied the initial lookup behavior reference; the current UI requires manual selection instead of its automatic skipping behavior. No ani-skip code was copied. The [AniSkip API documentation](https://api.aniskip.com/api-docs) and live JSON responses supplied the request/response contract. Community timestamps and release cuts can still differ; the toggle allows ordinary playback when timing is unsuitable.

## Progress compatibility

`WatchProgress` retains its existing episode ID/number, position, and duration fields. Its new `audio` and `watchedAt` JSON fields are optional: absent or unknown audio reads as SUB, and absent/negative watch time reads as zero. New writes keep favorites, manual completion, detail links, and existing progress values. Old app readers ignore the extra fields, so reverting the app preserves base progress; an old app save can discard the new audio/watch-time fields. No destructive migration or preference-key change is required.

## Boundaries and failure handling

- `AniTVApp` reads the TV's default WebView User-Agent once and falls back to Android's `http.agent` property if WebView is unavailable. A final fallback includes the TV's Android version and model. It passes this value to `HiAnimeSource` and Media3. Source calls use `HttpURLConnection` with 15-second connect and read timeouts, HTTPS validation, `User-Agent`, and `Referer`. Responses are limited to 8 MB. Jsoup parses HTML; `org.json` parses response bodies.
- Desktop diagnostics must distinguish client-specific blocking from Android failures. The 2026-10-13 investigation reproduced Cloudflare 1010 with a default desktop User-Agent while app-style requests and installed emulator search succeeded; validate the actual app before classifying search as broken.
- The source reports blocked requests, non-success HTTP responses, missing markup, missing supported playback servers, malformed player data, insecure links, and oversized responses. Player errors show a retry instruction. Full stream URLs, cookies, and tokens are not logged.
- Translation uses Google Cloud Translation Basic v2 (API-key authentication) and DeepL v2. Google ML Kit is keyless but prohibits TV use without prior written permission. DeepL English and Portuguese targets use `EN-US` and `PT-BR`. Keys are encrypted on-device and never logged. Requests go directly from the TV to the provider. DeepL advises against client-side API keys; personal users accept exposure risk if a device is compromised, while a distributed app should use a protected server proxy.
- Translation requests use HTTPS and short timeouts. The source VTT remains the fallback if translation fails; translation responses stay in playback memory and are not persisted.
- There is no official or stable HiAnime API contract. Update selectors and endpoints only after inspecting current responses, then update saved fixtures and tests.
- `ani-cli` was used only as a behavior reference. No GPLv3 code was copied.

Run `./gradlew :app:testDebugUnitTest :app:assembleDebug` after source or UI changes. Test D-pad focus, Select, Back, video, audio, seek, subtitles, detail caching, and quality selection on an Android TV before claiming full device support for this build.

## Signed source rules

`source/SourceRules.kt` validates schema 1 into typed immutable configuration. Selectors, extraction attributes, relative endpoint templates, named-property JSON paths, server/audio matching values, player variable, Base64/XOR flags, and the public obfuscation key are data. HTML and JSON-wrapped HTML are supported. There is no script engine, downloaded code, arbitrary array path language, new provider abstraction, or APK updater. Fixed HiAnime origin, numeric IDs, HTTPS, response limits, subtitle selection/requirements, and VTT parsing remain compiled.

`SignedRules` verifies RSA-3072 / SHA256withRSA signatures over exact Base64-decoded payload bytes before parsing. `app/src/main/resources/` bundles only the public DER key and initial signed envelope. Revision ordering rejects downgrades and different payload bytes at an unchanged revision. Schema and minimum APK version checks precede activation.

`MainActivity.onCreate` obtains `ProcessRules`, a process singleton reused after language/Activity recreation and by both coordinator and playback source instances. It starts one background check. Home does not await the network. `RulesRepository.snapshot()` waits only for the remainder of the single three-second startup window; each source operation captures it once, including detail's search fallback. A scheduled deadline freezes validated cached rules or bundled defaults. A newer verified download selected before the deadline freezes the process snapshot; late results cannot activate or write cache. The injected `RulesTransport` supports fixture/deadline tests without publishing test rules.

`GitHubRulesTransport` reads the fixed HTTPS GitHub Contents endpoint with raw media type, descriptive User-Agent, and conditional ETag. Redirects are rejected, downloads are bounded to 256 KiB, and read/connect waits respect the startup window. Non-success HTTP, offline, malformed, incompatible, bad-signature, revision conflict, and timeout outcomes retain usable local rules.

`RulesCache` stores a signed envelope and its accepted ETag together in private `files/source-rules/current.json`. Temporary files are flushed and atomically renamed on the same filesystem. A previous validated envelope/ETag remains in `previous.json`; interrupted temporary files are ignored. Cache reads verify signatures again and prefer the highest compatible local revision. A cache write failure retains the selected in-memory snapshot and reports that it could not persist. No library/progress preference keys change.

A read-only StateFlow exposes revision/outcome to existing Settings. English and Turkish strings report app version, rules revision, and checking/current/updated/unavailable/timeout/rejected/cache-write states. Existing focusable controls and Back stay in place. Signed rules have no manual rule-update action; APK actions belong to the separate updater.

`tools/publish-rules` runs `RulesPublicationTest` against the actual Kotlin parser and a separate `rules` worktree's sanitized fixtures/expected models. It signs exact editable bytes with the external PKCS#8 DER key, verifies against the bundled public key, checks revision ordering, and atomically writes the envelope. The rules branch has an independent orphan history and contains rules, fixtures, license, and publishing instructions. See `docs/RELEASE.md`.

Release lint required scoped Media3 `UnstableApi` opt-ins and `LocalResources`/`LocalConfiguration` reads in existing playback/caption/coordinator code. These fixes do not alter stream, progress, or library formats.

## GitHub APK updater

`update/Release.kt` owns stable numeric versions, exact release-asset contracts, HTTPS URL restrictions, and pure APK identity validation. `UpdateTransport.kt` owns the fixed latest-release endpoint, conditional requests, finite timeouts, 1 MiB metadata / 100 MiB APK limits, at most five allowed HTTPS redirects, streaming progress, cancellation, byte count, SHA-256, and server retry deadlines. It does not use `HiAnimeSource` or the signed-rules transport.

`UpdateRepository` owns observable check/download/install state and injected transport, clock, installed identity, and APK inspection. An executor performs requests and file validation. Synchronization deduplicates checks and downloads; foreground transitions cancel unfinished work. The first automatic attempt is due immediately, later attempts are daily even after failure, clock rollback is due, manual checks have a persisted 60-second debounce, and server deadlines override both. A 304 reuses validated cached metadata; failures preserve earlier information and successful timestamps with an error status.

`UpdateStore` atomically persists release metadata, ETag, attempts, successful check time, retry deadline, and last check problem under private `files/update`. APKs use only `cache/update`; partial files are removed on startup and after unfinished transfers. Ready files must pass byte/digest and injected identity validation again before reuse. Existing library, translation, detail cache, and rules storage are untouched. `ProcessUpdates` holds one repository per process, independent of the Activity and signed rules. Startup loads metadata, cleans partials, and revalidates cached APKs off the main thread. `MainActivity.onResume` rereads installed identity and installation permission, then asks for a due automatic check. Stop cancels unfinished transfer/validation; configuration recreation retains it. No worker, service, alarm, or background scheduler is registered.

`AniTVApp` observes updater state before the playback early return. Home inserts a keyed focusable notice after the main menu without requesting focus. Settings embeds `UpdateContent`, using existing TV Buttons, stable download-action identity, text/progress semantics, English/Turkish resources, and expandable plain-text notes. Short focusable note sections adapt to font scale so D-pad scrolling can expose long notes. Search, playback, translation, and source requests do not wait for updater requests.

`AndroidApkInspector` reads `GET_SIGNING_CERTIFICATES` package/archive information. The pure validator requires the fixed package, matching release versionName, newer versionCode and semantic version, compatible minimum SDK, and exact nonempty current signer set. `UpdateInstaller` revalidates bytes and identity off the main thread before posting a foreground-only Android action. It opens per-app unknown-source settings when permission is missing; return offers Install explicitly. Otherwise it sends `ACTION_VIEW`, APK MIME type, content URI/ClipData, and temporary read permission. `UpdateFileProvider` is non-exported and exposes only `cache/update/`. Missing activities/permission rejection are visible states. Returning from the installer reports an unchanged version without claiming success; startup/resume handles the real installed identity.

`src/debug/.../UpdateFixtureActivity` provides a local fixture transport, isolated metadata store, and `cache/update/fixture` directory for emulator-only verification. It reuses the shipping updater UI, inspector, FileProvider, lifecycle, and installer. Its Activity/manifest and local APK bytes are absent from release builds. Android tests inspect a same-debug-signer higher-code fixture and verify content-provider scope and focus; JVM tests cover transport, timing, persistence, cancellation, and identity rejection. No production endpoint or trust source is replaced.
