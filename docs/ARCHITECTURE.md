# AniTV architecture

AniTV is one Kotlin Android `app` module. Compose for TV owns navigation and screens; `LibraryStore` owns local favorites and progress; `AnimeDetailCache` owns cached title metadata and poster files; `HiAnimeSource` owns HiAnime requests and parsing; `SubtitleTranslator` owns Google/DeepL API requests; Media3 owns playback.

```text
Home → Search/results or local library → detail + episodes → available SUB/DUB → HLS + optional VTT player
Home featured Continue watching / detail Continue watching → saved episode + audio + position → fresh stream → player
        ui/AniTVApp                        HiAnimeSource       Media3
                         LibraryStore ← progress/favorite/completed
                         AnimeDetailCache ← description/facts/poster/timestamp
Playback Episodes → modal episode sidebar → selected episode + current SUB/DUB → fresh stream
Home → Settings → Android LocaleManager → English or Turkish resources
AniTVApp → TV WebView/HTTP User-Agent → HiAnimeSource + Media3 HTTP requests
Settings → TranslationSettingsStore → Android Keystore → provider key
Playback caption menu → TranslationSettingsStore → target language + caption style
Playback → HiAnimeSource VTT cues → SubtitleTranslator batches → timed Media3 SubtitleView overlay
```

## Flow

1. `AniTVApp` sends a query to `HiAnimeSource.search()` on `Dispatchers.IO`. The source reads `https://hianime.at/search?keyword=...` and parses `.film_list-wrap .flw-item` cards into `Anime` records, including each result's detail link.
2. Selecting a result or saved title loads episodes and details independently. `episodes()` reads `/api/theme/episode/list/{animeId}` and extracts `a.ep-item[data-id]`. `details()` reads the title page, parses `#ani_detail` for description and facts plus `.anisc-poster img[src]` for the portrait poster URL, and falls back to a search by title for older saved entries without a detail link.
3. `AnimeDetailCache` returns stored details and image bytes immediately. Entries under 24 hours old skip a network request. Older entries stay visible while `HiAnimeSource` fetches new metadata and poster bytes; a missing cached image also triggers refresh. The changed cache metadata key invalidates earlier wide-cover entries, so they refresh on first open. Android may evict files from the cache directory, which results in a new fetch. Home Continue watching and Favorites reuse this behavior through `rememberAnimeArtwork`; `LibraryContent` keeps favorite filtering and stable title keys, while the coordinator supplies card content. Each favorite card remains selectable during loading or artwork failure. Currently watching and Completed retain their existing text rows.
4. Selecting an episode calls `servers()`. The source reads `/api/theme/episode/servers?episodeId=...`; `parseServers()` returns only available ZokoAnime `sub`/`dub` entries with validated HTTPS embed links. When one audio version exists, the app starts it directly. When both exist, `EpisodeContent` offers Subtitled and Dubbed buttons. `stream(server)` reads the selected embed, and `parsePlayer()` decodes `window.__P` into an HTTPS HLS URL and optional VTT subtitle URL. SUB retains its subtitle requirement; DUB can play without captions. There is no dub language picker or audio translation; dubbed audio uses the source version. An error allows retrying the selected version or choosing another available version.
5. `Playback` builds a Media3 `MediaItem` and attaches an external VTT track when present. A dub without a VTT track disables the caption button and translation work. `DefaultHttpDataSource` sends the embed origin as `Referer` for stream and subtitle requests. It uses the same TV-derived User-Agent as `HiAnimeSource`. `PlayerView` renders video; Compose buttons handle the remote. Media3 track groups populate the optional quality selector. Controls hide on D-pad Down or after six seconds of play, and show on D-pad Up or Select. `ForegroundPlayer` observes the Activity lifecycle and creates a player only at Start. At Stop (including the physical Home button), it pauses, saves progress, and releases synchronously. Returning creates a new player at the saved position with the previous play/pause state. A late stream response while stopped cannot start playback. `DisposableEffect` removes the observer and releases on composition exit; repeated cleanup is harmless. Player changes restart translation and progress jobs; `PlayerView` detaches on disposal.

Playback's Episodes control opens `EpisodeSidebar` in a modal Compose Dialog. The sidebar receives title/current episode, the existing episode list, and independent loading/error state from the coordinator. Its keyed LazyColumn initially scrolls/focuses the current episode by ID, falling back to the first available episode or Close if empty. The current episode stays visible in the sidebar header and has a play icon, text marker, selected semantics, and distinct row background. The dialog confines focus and handles Back; dismissal returns focus to Episodes. The controls timeout pauses while the sidebar is open. Opening, navigating, or closing the sidebar does not change play/pause state. Selecting the current row only dismisses; selecting a different episode saves the outgoing position, then asks the coordinator to load it with the current audio version. The old player releases through the existing lifecycle/disposal path. Composition keys keep its cleanup callback bound to the outgoing anime/episode. A list retry calls `HiAnimeSource.episodes()` without clearing the active stream; stale title generations cannot replace the new title's list.

6. Playback's caption menu selects Off, Original, or Translate. Translate requires a configured provider and key. The language picker saves one of 15 target languages in `TranslationSettingsStore`; an unset target follows the app/TV locale. The style picker saves font, percentage size, background color, and text color in the same store. Original and translated cues use Media3 `SubtitleView` with the same style; translated cues appear in a timed overlay while the native text track is disabled. The default is white sans serif at 24 sp (100%) on an 80% opaque black rectangular background. Translation fetches and parses timed VTT through `HiAnimeSource`. `SubtitleTranslator` sends up to four cue strings per HTTPS request. The app translates the current/following cues first, then advances the batch as playback approaches the end of translated cues. Changing language restarts batching at the current playback position. On VTT or API failure, playback re-enables the original Media3 subtitle track and shows a notice.
7. `LibraryStore` saves favorites, completion, and one last episode/position per title as JSON in private `SharedPreferences`. Playback saves progress every five seconds and on exit. The completed archive changes only through the detail-screen button. Currently watching filters saved progress to non-completed titles. `continueWatching()` selects the eligible entry with the latest progress `watchedAt`; favorite/completion edits do not update that time. Ties, including older records without watch time, retain list order. The home section adds its heading and card only when an eligible title exists; no history, zero progress, and completed-only libraries add no section. It features one title; the existing Currently watching collection remains available for all titles. Detail offers resume for any title with a positive saved position. `resumeEpisode()` reconstructs the saved episode without advancing it, and the existing player seeks to the matching stored position. The coordinator chooses the saved audio if available; otherwise it asks the user to select available audio. It fetches fresh server/embed data instead of saving expiring stream URLs. Title/episode-list loads keep a separate request generation from stream loads so home resume can populate the detail page for Back while playback prepares.
8. Settings reads and sets Android `LocaleManager.applicationLocales`. An empty locale list follows the system; explicit `en` or `tr` choices persist in Android and cause a configuration change. `TranslationSettingsStore` encrypts the API key with Android Keystore and stores the provider choice and caption style in private preferences. Android string resources localize app controls and source errors. `HiAnimeSource` emits typed failure codes without depending on Android resources.

The UI uses `remember` state for query, results, selection, loading, and errors. The page uses `rememberSaveable` so Settings remains open after a language change. Separate title and transient request counters ignore late responses after another selection or Back. Search query and results are not persisted across process death; library and detail cache state are.

## Progress compatibility

`WatchProgress` retains its existing episode ID/number, position, and duration fields. Its new `audio` and `watchedAt` JSON fields are optional: absent or unknown audio reads as SUB, and absent/negative watch time reads as zero. New writes keep favorites, manual completion, detail links, and existing progress values. Old app readers ignore the extra fields, so reverting the app preserves base progress; an old app save can discard the new audio/watch-time fields. No destructive migration or preference-key change is required.

## Boundaries and failure handling

- `AniTVApp` reads the TV's default WebView User-Agent once and falls back to Android's `http.agent` property if WebView is unavailable. A final fallback includes the TV's Android version and model. It passes this value to `HiAnimeSource` and Media3. Source calls use `HttpURLConnection` with 15-second connect and read timeouts, HTTPS validation, `User-Agent`, and `Referer`. Responses are limited to 8 MB. Jsoup parses HTML; `org.json` parses response bodies.
- Desktop diagnostics must distinguish client-specific blocking from Android failures. The 2026-10-13 investigation reproduced Cloudflare 1010 with a default desktop User-Agent while app-style requests and installed emulator search succeeded; validate the actual app before classifying search as broken.
- The source reports blocked requests, non-success HTTP responses, missing markup, missing supported playback servers, malformed player data, insecure links, and oversized responses. Player errors show a retry instruction. Full stream URLs, cookies, and tokens are not logged.
- Translation uses Google Cloud Translation Basic v2 (API-key authentication) and DeepL v2. Google ML Kit is keyless but prohibits TV use without prior written permission. DeepL English and Portuguese targets use `EN-US` and `PT-BR`. Keys are encrypted on-device and never logged. Requests go directly from the TV to the provider. DeepL advises against client-side API keys; personal users accept exposure risk if a device is compromised, while a distributed app should use a protected server proxy.
- Translation requests use HTTPS and short timeouts. The source VTT remains the fallback if translation fails; translation responses stay in playback memory and are not persisted.
- There is no official or stable HiAnime API contract. Update selectors and endpoints only after inspecting current responses, then update saved fixtures and tests.
- `ani-cli` was used only as a behavior reference. No GPLv3 code was copied.

Run `./gradlew :app:testDebugUnitTest :app:assembleDebug` after source or UI changes. Test D-pad focus, Select, Back, video, audio, seek, subtitles, detail caching, and quality selection on an Android TV before claiming full device support for this build.
